RESTREAM INFRASTRUCTURE

Zero-Latency Restream Service

Low-Latency SRT Ingest, Direct SRT Playback, and Protected WebRTC Monitoring

Project Overview

This project is a portable low-latency restreaming platform built around SRT, MediaMTX, FFmpeg, Nginx, and Docker. Up to four broadcasters can publish H.264 and AAC feeds to the server over SRT. Hosts can read the original SRT feeds directly into OBS, while browser-compatible copies are generated automatically for private WebRTC monitoring.

The public landing page is kept separate from the private streaming portal. Live monitoring, setup guides, generated connection URLs, and backend API access are protected behind authentication, while SRT publishing and reading require automatically generated credentials.

The Technology Stack

Docker Containerization

Nginx and MediaMTX run as containerized services, making the application stack easy to deploy, recreate, update, and move between compatible Linux servers.

MediaMTX & SRT

Broadcasters publish directly to MediaMTX using SRT. MediaMTX authenticates publish and read connections, routes the four stream slots, and allows hosts to pull the original feeds directly into OBS without video transcoding.

FFmpeg Processing

When a source becomes available, MediaMTX launches FFmpeg to copy the original H.264 video while converting AAC audio to Opus. The result is republished internally as a browser-compatible stream for WebRTC playback.

Nginx Security & Routing

Nginx serves the web interface, handles HTTPS and HTTP Basic Authentication, and reverse-proxies the internal MediaMTX WebRTC HTTP interface and Control API without exposing those services directly to the Internet.

Lightweight Browser Monitoring

The browser interface uses lightweight vanilla JavaScript and the MediaMTX Control API to monitor which stream slots are currently active. WebRTC players are only displayed when their corresponding feeds are available.

  • Live Status Monitoring: The frontend polls the protected MediaMTX API to determine which stream slots are currently online.
  • Automatic Offline Handling: When a source disconnects, the player is removed and the interface returns that slot to its offline state automatically.
  • Responsive Multi-View: The interface supports a four-stream grid as well as isolated single-stream views, with responsive behavior for desktop and mobile displays.
  • Protected Setup Pages: Streamers and hosts can retrieve deployment-specific SRT URLs from private setup guides instead of manually constructing connection strings.

Built With

This low-latency streaming environment stands on the shoulders of giants. A massive thank you to the developers and maintainers of the open-source tools and protocols that make this project possible:

  • Secure Reliable Transport (SRT) : Originally developed by Haivision. Used for low-latency stream publishing and direct host playback.
  • WebRTC : Used for low-latency browser monitoring through MediaMTX.
  • FFmpeg : Used to preserve the H.264 video stream while converting AAC audio to Opus for browser playback.
  • Nginx : Used for the web frontend, authentication, HTTPS termination, and reverse proxying.
  • Docker : Used to containerize the server application stack.
  • Let's Encrypt & Certbot : Used for automated HTTPS certificate issuance and renewal.
